Architecture · MCP Gatehound

One binary, one lifetime

The window is not the application. A single Rust process owns the listener, the policy, the database and the child processes; the webview holds no state of record and reads everything through IPC. Closing the window hides it — quitting the app is the gateway going down.

The rule that shapes it

The window holds no state of record. Every screen reads through IPC and re-reads when the core pushes an event, so there is one copy of the truth and the window can be closed, reopened, or absent without the gateway noticing.

Rust side

axum · tokio · rusqlite (bundled, WAL) · reqwest + rustls · serde / toml · sha2 · tracing. Three crates: core, a headless binary, and the Tauri shell.

Window side

Vanilla TypeScript and Vite. No framework, no state library, no component kit — one paint() that writes HTML only when it differs, and a CSS custom-property design system.
